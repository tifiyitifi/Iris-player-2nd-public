# Virtual Cut - rule register

One observable behaviour per row. Coverage tokens are defined in `../../README.md`.
Rows are append-only: a rule that stops being true is superseded, never deleted.

| ID | Rule | Edge | Behaviour | Why | Coverage |
| --- | --- | --- | --- | --- | --- |
| FC-01 | Pair by recorded source name | `mediaFileName` wins | WHEN a project records a source file name, THE SYSTEM SHALL bind it to that video and not to a stem-similar sibling | LosslessCut writes the name; a guess can cut the wrong episode | `F:fake_cut_project_index_test#pairs a project by its recorded mediaFileName`; `F:fake_cut_pairing_test#the recorded mediaFileName is authoritative over the project stem`; `D:0001` |
| FC-02 | Stem fallback | Name unreadable | WHEN the recorded name is unreadable, THE SYSTEM SHALL pair by the LosslessCut project stem, including its default suffixes | hand-edited and older projects omit the name | `F:fake_cut_pairing_test#a project without mediaFileName pairs by stem (LosslessCut suffixes)`; `F:fake_cut_project_index_test#falls back to the -proj stem when mediaFileName cannot be read`; `D:0001` |
| FC-03 | Explicit directory cache | Failed listing | WHEN a directory is listed, THE SYSTEM SHALL cache it until an explicit invalidate, and SHALL NOT cache a failed listing as empty | one IO blip used to disable 虚拟剪播 for a folder all session | `F:fake_cut_project_index_test#listings are cached until invalidated`; `F:fake_cut_project_index_test#a FAILED listing is not cached as "no projects"`; `D:0007` |
| FC-04 | Parse LosslessCut JSON5 | v1/v2/v3 | WHEN a `.llc` is read, THE SYSTEM SHALL accept numeric seconds and timecode ranges across supported versions and SHALL reject invalid content without throwing | hand-edited files are common | `F:fake_cut_llc_parser_test#v3 timecode strings`; `F:fake_cut_json5_test#reads the LosslessCut project shape`; `D:0002` |
